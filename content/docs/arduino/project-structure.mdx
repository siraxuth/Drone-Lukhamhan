โปรเจกต์ของชมรมไม่ได้อยู่ในไฟล์เดียว มี 18 ไฟล์ (ตรงกับไฟล์ที่ดาวน์โหลดได้ใน [ติดตั้ง Arduino IDE](/docs/arduino/install-ide)) ทั้งนี้เพื่อให้แก้ทีละส่วนโดยไม่กระทบส่วนอื่น หน้านี้เป็นแผนที่ว่าอะไรอยู่ที่ไหน

## 1. กฎของ Arduino ที่ต้องรู้ก่อน

- Sketch คือ **โฟลเดอร์** ชื่อโฟลเดอร์ต้องตรงกับไฟล์ `.ino` หลัก (`drone_sanam5/drone_sanam5.ino`)
- ไฟล์ `.ino` ทุกไฟล์ในโฟลเดอร์ถูก **ต่อรวมเป็นไฟล์เดียว** ก่อนคอมไพล์ จึงเรียกฟังก์ชันข้ามไฟล์ได้โดยไม่ต้อง `#include`
- เพราะรวมเป็นก้อนเดียว **ชื่อฟังก์ชันห้ามซ้ำ** และ **error ในไฟล์ไหนก็ล้มทั้งชุด** แม้เป็นโหมดที่ไม่ได้เลือก
- ไฟล์ `.hpp` และ `.cpp` ไม่ได้ถูกรวมแบบนั้น `.hpp` ต้อง `#include` เอง

### ตัวอย่างชีวิตจริง: สมุดเล่มเดียวหลายบท

ลองนึกถึงสมุดจดที่แต่ละบทอยู่ในกระดาษคนละแผ่นแต่เย็บเป็นเล่มเดียวกัน อ่านบทไหนก็อ้างถึงบทอื่นได้ แต่ถ้าสองบทตั้งชื่อหัวข้อเหมือนกันสับสนทันที ไฟล์ `.ino` ก็เหมือนกัน

## 4. mode_config.hpp: เลือกโหมดบรรทัดเดียว

```cpp
// mode_config.hpp
#define FLIGHT_MODE_DRONE_MISSION              1
#define FLIGHT_MODE_AVIATION_MASTERY           2
#define FLIGHT_MODE_DRONE_INNOVATION_CHALLENGE 3

#define ACTIVE_FLIGHT_MODE   FLIGHT_MODE_DRONE_MISSION
```

`#define` คือคำสั่งให้ตัวประมวลผลก่อนคอมไพล์ "ค้นหาแล้วแทนที่" ชื่อข้างซ้ายด้วยค่าด้านขวา ไม่ใช้ RAM เลย อยากสลับโหมดก็แก้ `FLIGHT_MODE_DRONE_MISSION` เป็นชื่ออื่นแล้วอัปโหลดใหม่

## 5. drone_sanam5.ino: ตัวกระจายโหมด

```cpp
// drone_sanam5.ino
#if  ACTIVE_FLIGHT_MODE == FLIGHT_MODE_DRONE_MISSION
  #define MODE_SETUP  setupDroneMissionMode
  #define MODE_LOOP   loopDroneMissionMode
#elif ACTIVE_FLIGHT_MODE == FLIGHT_MODE_AVIATION_MASTERY
  #define MODE_SETUP  setupAviationMasteryMode
  #define MODE_LOOP   loopAviationMasteryMode
#elif ACTIVE_FLIGHT_MODE == FLIGHT_MODE_DRONE_INNOVATION_CHALLENGE
  #define MODE_SETUP  setupDroneInnovationChallengeMode
  #define MODE_LOOP   loopDroneInnovationChallengeMode
#else
  #error "ACTIVE_FLIGHT_MODE ตั้งค่าไม่ถูก — เปิด mode_config.hpp แล้วตั้งเป็น FLIGHT_MODE_* ตัวใดตัวหนึ่ง"
#endif

void setup() {
  drone.beginDefault();   // เริ่มระบบ + I2C กับ Flight Controller (ทุกโหมดใช้ร่วมกัน)
  MODE_SETUP();           // setup เฉพาะของโหมดที่เลือก
}

void loop() {
  MODE_LOOP();            // loop เฉพาะของโหมดที่เลือก (คอยอ่านปุ่มจากรีโมท)
}
```

`#if / #elif / #else` ทำงานตอน **คอมไพล์** เลือกชื่อฟังก์ชันของโหมดที่ตั้งไว้ ที่เหลือไม่ถูกรวมเข้าโปรแกรม ถ้าตั้งเลขผิด `#error` หยุดคอมไพล์พร้อมข้อความชัดเจน ดีกว่าให้ผ่านแล้วโดรนเงียบ

ในโหมด Mission `loop()` ที่ถูกเรียกคือฟังก์ชันที่ผูกปุ่มเข้ากับ handler

```cpp
// Drone_Mission.ino
void loopDroneMissionMode() {
  drone.onKey1(DroneMission_KEY_1_handle);
  drone.onKey2(DroneMission_KEY_2_handle);
  // ... KEY 3 ถึง KEY 9 แบบเดียวกัน
  drone.onKey10(KEY1_mode1);          // KEY 10 เรียก KEY1_mode1() ไม่มี KEY 11
  drone.onKey12(DroneMission_KEY_12_handle);
  drone.onKey13(DroneMission_KEY_13_handle);
  drone.onKey14(DroneMission_KEY_14_handle);
}
```

`DroneMission_KEY_1_handle` ไม่มีวงเล็บ เพราะเป็นการส่ง "ตัวฟังก์ชัน" ไปให้ `onKey1` ถือไว้เรียกทีหลัง (อธิบายที่หน้า [ฟังก์ชันและอาร์เรย์](/docs/arduino/cpp-functions-arrays))

## 6. config.hpp: ค่าที่แก้บ่อยที่สุด

ค่าที่จูนตามสนามและแก้บ่อยที่สุดอยู่ที่นี่ (ตัดมาเฉพาะบางบรรทัด)

```cpp
// config.hpp
constexpr uint16_t HEIGHT_FLIGHT   = 100;
constexpr uint16_t HEIGHT_SHOOT    = 120;
constexpr float MS_PER_CM_FWD       = 15.46f;
constexpr float MS_PER_CM_BACK      = 15.16f;

const int S_CLOSE = 1500;
const int S_LEFT  = 1200;
const int S_RIGHT = 2000;
```

`constexpr` กับ `const` คือค่าคงที่ที่ห้ามเปลี่ยน ใช้ชื่อแทนเลขดิบเพื่อให้โค้ดอ่านออก `HEIGHT_SHOOT` ชัดกว่า `120`

บรรทัด `MS_PER_CM_FWD = 15.46f` มีความหมายว่า บินไปข้างหน้า 1 cm ใช้เวลา 15.46 ms สั่ง 100 cm จึงรอประมาณ 1,546 ms ในไฟล์จริงมีค่าเก่า `16.39f` คอมเมนต์ทิ้งไว้ข้างบนบรรทัดนี้ แสดงว่าค่านี้ถูกปรับมาแล้วอย่างน้อยหนึ่งครั้ง วิธีปรับเองคือสั่งบินจริง 100 cm วัดระยะที่ได้ แล้วแก้ตัวเลขตามสัดส่วน (ดูวิธีเต็มที่ [ระยะทางกับเวลา](/docs/code/distance-time))

## ลองทำ

1. เปิด `mode_config.hpp` เปลี่ยน `ACTIVE_FLIGHT_MODE` เป็น `FLIGHT_MODE_AVIATION_MASTERY` แล้วกด Verify ดูขนาดโปรแกรม (ที่คอมไพล์กับชุดดาวน์โหลดจริง บอร์ด Arduino Nano ATmega328P Old Bootloader: โหมด Mission 7,032 ไบต์ โหมด Aviation Mastery 5,654 ไบต์ โหมด Innovation Challenge 6,768 ไบต์ เล็กลงเพราะโค้ดโหมดอื่นไม่ถูกใช้ จึงไม่ถูกใส่ลงชิป)
2. แก้เป็นเลขที่ไม่มี เช่น `#define ACTIVE_FLIGHT_MODE 9` กด Verify จะเห็น `#error` พร้อมข้อความไทยของจริง แล้วแก้กลับ
3. หาว่า `HEIGHT_SHOOT` ถูกใช้กี่ที่ด้วย `grep -n HEIGHT_SHOOT *.ino *.hpp *.cpp`

## พังตรงไหนบ่อย

- **ชื่อฟังก์ชันซ้ำข้ามไฟล์** เช่น เขียนฟังก์ชัน `blink()` ในสองไฟล์ `.ino` จะขึ้น `redefinition of ...`
- **error ในไฟล์โหมดที่ไม่ใช้** ล้มทั้งชุด ต้องแก้ หรือคอมเมนต์ออกทั้งไฟล์
- **แก้ `config.hpp` แล้วค่าไม่เปลี่ยน** ลืมกดอัปโหลดใหม่ ค่าพวกนี้ถูกฝังตอนคอมไพล์
- **ใช้ `#include` กับไฟล์ `.ino`** ไม่ต้อง และอย่าทำ ไฟล์ `.ino` รวมกันให้เองแล้ว
